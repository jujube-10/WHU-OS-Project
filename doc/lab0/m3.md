echo 在用户态执行 `write` 循环之间的普通指令时被时钟打断

## 硬件陷入（U→S）

```text
prepare_return() 已设 stvec=uservec, sstatus.SPIE=1(用户态开中断), SPP=0
stimecmp 到期 → 硬件置 sip.STIP; 因 SIE=1 且 SSTATUS.SIE=1 而响应:
   scause = 0x8000000000000005   (bit63=1 表中断, 低 5 位=5 即 S 定时器中断)
   sepc   = 被打断的用户 PC
   sstatus: SPP←0(来自U), SPIE←SIE(旧值1), SIE←0(进入内核自动关中断)
   PC     ← stvec = uservec (TRAMPOLINE 页)
```

## uservec 现场保存

```text
[S], 用户页表仍生效（关键：此时 satp 还没切换）
  csrw sscratch,a0             ; 借 sscratch 暂存用户 a0
  a0 ← TRAPFRAME
  保存 ra/sp/gp/tp/t0-t6/s0-s11/a1-a7 → p->trapframe   (现场保护, 见 trapframe 布局)
  a0 ← sscratch; sd 到 trapframe->a0 (偏移112)
  sp ← trapframe->kernel_sp     ; ═► 切到 KS(echo) 栈顶
  tp ← trapframe->kernel_hartid ; 恢复 hartid(供 cpuid)
  t1 ← trapframe->kernel_satp
  sfence.vma; csrw satp,t1; sfence.vma   ; ═► 切内核页表
  jalr trapframe->kernel_trap   ; ═► usertrap()
```

## usertrap 判定， clockintr

```text
usertrap:  assert(SPP==0);  stvec←kernelvec   ; 此后内核态中断走 kernelvec
           p->trapframe->epc = r_sepc()        ; 保存用户 PC
           scause != 8（非 syscall）→ devintr()
             devintr(kernel/trap.c:187): scause==0x...5 →
                 clockintr(kernel/trap.c:167): cpuid0 者 ⛨spin:tickslock → ticks++ → wakeup(&ticks) → 释放
                 w_stimecmp(r_time()+1000000)   ; 预约下一次中断
             return 2
           which_dev==2 → yield()               ; 让出cpu
```

> 同一 `devintr()/clockintr()` 被 `usertrap` 与 `kerneltrap` 共用。区别：用户态路径 `usertrap` 无条件 `yield`；内核态路径 `kerneltrap`仅在 `myproc()!=0` 时 `yield`（避免在无进程的引导期切走），且会在 `yield` 后重写 `sepc/sstatus`（因为 `yield` 里可能再次陷入）。
## yield → sched 

```text
yield(): acquire(&p->lock)          ⛨spin:p->lock
         p->state = RUNNABLE
         sched():
            校验: holding(p->lock), noff==1, state!=RUNNING, !intr_get
            intena ← mycpu()->intena
            swtch(&p->context, &mycpu()->context)   ; 保存 echo 内核上下文, 载入调度器上下文
            mycpu()->intena ← intena
         release(&p->lock)
```

`swtch` 后 CPU 栈从 **KS(echo)** 切到 **SCH（stack0）**，回到 `scheduler`（`kernel/proc.c:429-470`）的 `swtch(&c->context,&p->context)` 之后继续：

```text
scheduler: c->proc=0; release(&p->lock)   ; 释放刚选出的旧进程 p 的锁
           再次扫描 proc[] 找 RUNNABLE 进程(如 sh 或 init)
           找到后: acquire(&p->lock) → state=RUNNING → c->proc=p
                   swtch(&c->context,&p->context)   ; 交接给新进程
```

> 锁的所有权交接：`scheduler` 在 `swtch` 进入进程时**持有该进程 p->lock**，进程回来前由 `forkret` 或 `sched` 负责释放/重取（`kernel/proc.c:446-456`、`kernel/proc.c:519-520`）。

## echo 再次被调度，sret 返回用户态

当 echo 下一轮被调度器选中，从 `sched()` 里的 `swtch` 返回，`release(&p->lock)`，回到 `usertrap` 的 `yield()` 之后：

```text
usertrap: prepare_return()(kernel/trap.c:100):
            intr_off()                       ; 关中断，避免切换 stvec 期间内核态误入 uservec
            stvec ← uservec
            trapframe->kernel_satp/sp/trap/hartid ← 内核页表/KS(echo)/usertrap/hartid
            sstatus: SPP←0, SPIE←1           ; 返回目标=用户态, 用户态恢复开中断
            sepc ← p->trapframe->epc         ; 恢复被时钟打断的用户 PC
          返回 satp(用户页表) 到 trampoline userret
userret(kernel/trampoline.S:101-153):
            sfence.vma; csrw satp,用户页表; sfence.vma   ; 切回用户页表
            从 trapframe 恢复全部用户寄存器(含 sp→用户栈, a0)
            sret                              ; ──► 用户态原 PC 继续执行
```
